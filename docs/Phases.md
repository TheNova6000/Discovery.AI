## Phase 3 — Single Ground Agent loop [VERIFIED]
- `GroundAgent` class: receive a Question → generate sub-questions/hypothesis via the Question Engine → detect insufficient evidence/boundary conditions → produce a typed result, **recurse into child Ground agents if deeper decomposition is needed**, or escalate. No separate `DomainAgent`/`SubdomainAgent` classes (Rules.md rule 8) — recursive Ground agents are the mechanism.
- SQLite state store for a single agent's pausable/resumable state.
- **Verify:** run a Ground Agent on one question end-to-end, kill the process mid-run, restart, and confirm it resumes from checkpointed state rather than restarting from scratch. — `scripts/verify_phase3.py`.
- Since delivered, superseded: the original batch-decompose design (decide all sub-questions upfront) was replaced with the sequential/incremental loop actually described above (`_investigate_loop` — one sub-question at a time, folded into `known`, then re-decide) after a live evaluation found the batch version never adapted mid-investigation — see Memory.md. Master-level structural-judgment bias (near-decomposability, Herbert Simon 1962) added to `decide_next_step`'s prompt and empirically validated against a falsification test — Architecture.md §0.1.

## Phase 4 — Master agent + message bus + spawn budget [VERIFIED]
- `MasterAgent` wrapping recursive `GroundAgent` calls, built on LangGraph's core engine for the state machine/checkpointing. Two-tier by default (Master + Ground); intermediate structure only emerges as Ground agents recurse.
- **Hard spawn budget enforced in the Master before any spawning** (Rules.md rule 10) — e.g. default to 1-3 Ground agents for a simple query, require an explicit complexity signal to scale beyond that. This is written and tested in this phase, not added later.
- Typed message bus (asyncio queues + Pydantic message models), **vertical only, no lateral peer channel** (Rules.md rule 9), implementing the message taxonomy from Rules.md/Architecture.md.
- ~~Priority task queue (SQLite table with priority column) feeding agent scheduling~~ — **not built as delivered**: `MasterAgent` schedules its selected Ground Agents via a single `asyncio.gather` with no priority ordering. Folded into "Later / not yet scheduled" below (cost/priority-based task allocation) rather than left as an unmet Phase 4 bullet — see Architecture.md §2's Agent Runtime entry and Memory.md for why this was simplified during implementation.
- **Verify (two checks):** (1) a Ground Agent raises `BOUNDARY_HIT`, confirm the message propagates up the parent chain and the Master logs an `EXPANSION_REQUEST` decision (accept/reject); (2) feed the Master a deliberately simple, narrow query and confirm it does NOT spawn more than the small default budget of Ground agents — this is the regression test for the exact failure Anthropic's own orchestrator hit (Architecture.md §0). — `scripts/verify_phase4.py`, both checks pass.

## Post-Phase-5 — Epistemic layer (ad hoc research, not a numbered phase; feeds Phase 7)
Not part of the original phase sequence — opened by a design discussion questioning whether synthesis can be trusted just because its inputs were investigated. Fully detailed in Architecture.md §0.2-§0.5 and Memory.md (2026-08-28 entries); summarized here only to keep Phases.md accurate about what exists before Phase 6/7 build on top of it:
- **Structural provenance** (`backend.agents.trace_claim`) — **[VERIFIED]**. Classifies how a resolved question's answer was derived (direct/derived/synthesized/unresolved) from the AgentState tree every run already persists. SQLite-only, no Neo4j.
- **Content provenance** (`backend.questions.audit_synthesis`) — **[VERIFIED, 3 sessions]**. A separate auditor call decomposes a synthesized answer into atomic propositions and classifies each as traceable to the investigated material or not — a traceability judgment, explicitly not a truth judgment. One true-positive detection plus two clean negative controls, including one that specifically ruled out the auditor becoming a truth/consensus detector.
- **Claim relationships** (`backend.questions.analyze_claim_relationships`) — **[PARTIAL, three experiments]**. Six-label taxonomy (complementary/alternative_explanation/contradictory/conditional/sequential/unrelated). Reliably avoids inventing false conflict. Three controlled experiments on one pair (original unparaphrased wording, three different target questions) **confirmed `R = f(claim_a, claim_b, question)`**: the identical pair in identical wording returned `sequential`, then `complementary`, then `alternative_explanation` as only the question changed — including successfully eliciting competing-explanation detection once a question demanded a single primary cause, which two broader "why"/"how" framings did not produce. Real, load-bearing finding for how relationships should eventually be represented (question-relative, not intrinsic to a claim pair) — but still only demonstrated on one claim pair; not yet generalized, and no representation has been designed for where a contextual relationship should live (Architecture.md §0.5).
- None of these three are wired into the default agent/synthesis path — standalone, independently-callable tools only, pending further validation.

## Phase 7 — Abstraction-change protocol + conflict resolution [VISION — not started]
- Implement expand/contract/split/merge/reframe operations on the Abstraction Manager, triggered by accepted `EXPANSION_REQUEST`s.
- Conflict resolution: when two branches produce contradictory claims about the same entity, surface both with evidence rather than overwriting (Section 31 of the Agentic Architecture spec).
- **Not starting from zero anymore:** the Post-Phase-5 epistemic layer (above) already supplies real, if partial, groundwork — `analyze_claim_relationships` is a first attempt at exactly the judgment this phase needs ("do these claims conflict, or are they just different"), and `Claim.contradictions` already exists in the schema waiting to be populated. The one experiment run so far shows the mechanism reliably avoids false conflict but has not yet demonstrated real competing-explanation detection — Phase 7 should not begin by inventing this judgment from scratch, and should not begin at all until the controlled follow-up experiment (Architecture.md §0.5) either confirms or rules out that the earlier result was a representation problem rather than a reasoning one.
- **Verify:** manufacture a scenario where two Ground Agents reach different conclusions about the same entity from different dimensions, confirm the system surfaces both claims with their evidence rather than silently picking one.
